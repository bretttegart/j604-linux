## Interpretation

**Identical failure.** With the strobe added, Linux's warm
construction performs m1n1's `rtkit_boot` steps in order — CPU start,
INIT, HELLO, EPMAP, AP ON — and the firmware still crashes on the
sleep request. The CPU-start strobe candidate is eliminated, and with
it the last message/register-level construction difference the audit
found for the warm path.

Two pre-registered follow-ups remain:

1. **The branch-2 INIT change is still untested.** It is inert in a
   warm run. The E4 kernel run as the cold L1 cell (m1n1 cycle first,
   then a Linux cold boot) exercises branch 2 with the INIT send —
   the cheapest remaining test, already built.
2. **PMGR/reset provenance (E5).** Every m1n1 sleep-capable session
   followed m1n1's own sleep + CPU stop + `pmgr_reset(ANS/ANS2)`
   history; every Linux session follows iBoot's handoff plus genpd
   attach. Having the diagnostic m1n1 run its proven cycle and hand
   the live session to Linux in the same power session separates
   session history from session construction.
