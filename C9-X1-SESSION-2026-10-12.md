## Result

The session reproduced the known failure exactly (no IOP SLEEP ACK,
prepare −62, one endpoint-1 receive at +0 ms) — and, for the first time on
the warm path, exported the firmware's complete crashlog.

## The crashlog

- `RTKIT: CO-PROCESSOR HAS CRASHED` immediately after the sleep send.
- CLHE VERSION=771 DECLARED=4BA0 FLAGS=A ALLOCATED=8000.
- CVer payload 0x90, MATCH=YES; UUID A100001021401ED5A178000201401ED5;
  base candidate 0xD8C000. Crg8 payload 0x350 at offset 0xE0, MATCH=YES —
  the same section lengths as the C5/C6 cold-boot crashlogs.
- Crash time 9619608371.
- Exception dump: `== EXCEPTION TAKEN FROM EL1H ==`
  - PSR = 0x600002C5
  - PC = 0xDA24E8 → image offset 0x164E8 against the CVer base candidate
    (the C6 cold crash reported from offset 0x164F0 — same site family).
  - ESR low32 = 0xBE000000 → EC 0x2F, an SError (asynchronous external
    abort). Identical to the cold-boot crashes.
  - FAR = 0x49F020000 — CRC-verified (page 7). The cold crashes faulted at
    0x49F008000: the same 0x49F0xxxx window, which the C9-REVIEW ADT audit
    (433 nodes, 544 register ranges, zero decode errors) found in NO
    register range in either bus form (0x29F0xxxx) or AP form.
  - SP = 0xFE4F80; full register set on verified page 7 (transcript in the
    run directory).
- Ccst section (task 14): frames PC = DA24E8, D99838, D94C58, DC74B8,
  DA0854, DA68BC. Casc section: L2C_STS=0x80, L2C_ADR and LSU_STS both
  latch the faulting address 0x49F020000.
- The endpoint-1 message Linux received at +0 ms (word 001051000BC40000)
  references the crashlog buffer (IOVA 0x1000BC40000, size 0x8000 — the
  buffer freed at remove; size matches CLHE ALLOCATED=8000).

## The firmware's own mailbox history (CMBX, 128 entries)

Decoded inside the crashlog. The tail is CRC-confirmed:

- slot 125: AP QUIESCED request, 00B0000000000010
- slot 126: AP QUIESCED ack, 00B0000000000010
- slot 127: IOP SLEEP request, 0060000000000001 — the LAST entry

No ACK entry follows. The firmware recorded the sleep request and died
processing it; the missing ACK is missing because it was never generated,
not because it was lost in transit or mishandled by Linux.

## Conclusion

The warm sleep crash and the cold boot crash are the same fault: while
handling the sleep request (warm) or boot (cold), the ANS firmware takes
an SError on an access to the unmapped 0x49F0xxxx window and dies before
it can answer. Linux-side construction, session history, message content,
and receive handling are all eliminated by the preceding C9 cells; what
remains different in Linux-built sessions is some state that decides
whether that access faults — power, clock, fabric, or the firmware's own
mapping for that window.
