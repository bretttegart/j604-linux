## Findings

1. **The tethered instrumented path is green.** With m1n1-current (2b0142c4) the
   ANS wakes (branch 3), enumerates, and reads — kernel A + your common init
   design is validated end to end.
2. **Cold-path failure point, first time seen from the kernel side:** firmware
   completes HELLO/EPMAP (kernel passes the epmap wait), then the IOP
   power-state ACK never arrives; the kernel times out (-ETIME) and the
   firmware crashes with Client 0 (NAND-facing ring) never initialized. The
   crash begins before any NAND contact, same as raw52 — but now the timeout
   is localized to the IOP-ACK wait specifically.
3. **Explicit INIT alone is refuted as the (sole) cause.** Kernel B sends
   SET_IOP_PWR_STATE(INIT) via `apple_rtkit_wake()` in branch 2 and fails
   bit-for-bit identically (same registers, same -62, same crashlog shape).
   Whatever the firmware is waiting for before it will ACK IOP power, INIT by
   itself doesn't satisfy it — or the problem is upstream (state the firmware
   was left in before CPU RUN).
4. **BASE-0 anomaly (unisolated):** the frozen 579aa227 kernel + old m1n1
   c87cf83b ALSO crashed the ANS while tethered (Brett's photo), contradicting
   the raw50-era tethered success on kernel 5b94073c. TETHER-A (kernel A +
   m1n1-current) passes. So something in {old m1n1 build c87cf83b, frozen
   kernel 579aa227, stale ANS state from the previous boot} can break even the
   tethered path. Not isolated further — flagged because it bears on how much
   we can trust "tethered works" as a baseline.
5. **Measurement notes:** (a) your init's summary CPU_CONTROL/BOOT_STATUS
   parse worked on the cold branch (00000010/00000000) but showed UNKNOWN on
   the tethered branch — cosmetic parse gap, non-blocking. (b) My first
   TETHER-A attempt was misrecorded as "missing diagnostics": the webcam
   mostly frames Brett's desk monitor, not the laptop; the pager was running
   all along. Phone photos are the reliable channel here. (c) The 1 MiB
   printk ring held everything (2244 lines, 0 gaps) — LOG_BUF_SHIFT change
   did its job.
