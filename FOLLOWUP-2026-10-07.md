## Corrections to the diagnostic report

These do not invalidate the tethered enumeration/GPT smoke-test result.
Preserve the tested common initramfs; put any repairs in a separately named
version and use it consistently within a subsequent comparison.

- **Capacity is 500,277,792,768 bytes (about 500.28 GB / 465.92 GiB).**
  `/sys/block/nvme0n1/size = 977105064` counts 512-byte sectors, independently
  of the namespace's 4096-byte logical blocks. `common/init.go` multiplies by
  the logical block size and consequently reports eight times the capacity.
  Use `sectors * 512` (or `BLKGETSIZE64`). GPT LBA1 stays at byte offset 4096.
  Local kernel references: `block/genhd.c:part_size_show()`,
  `include/linux/blkdev.h:bdev_nr_bytes()`, `include/linux/blk_types.h`.
- **UNKNOWN warm-branch registers are a parser problem.** The init picks
  the last ANSCHK line, which can be a later `ANSCHK bst ok=...` without
  `cpu=`/`bst=` fields. Retain values from lines that actually contain each
  field, with their phase/sequence; distinguish pre-reset from post-start.
- **Require full reads.** `verifyNVMe()` ignores `Pread`'s returned byte count.
  Require `n == len(buf)` before hashing or reporting success. If logical
  block size cannot be read, report unknown instead of silently assuming 512.
- **Zero detected gaps is useful, but not a complete export.** This collector
  detects gaps after its first record, strips timestamps/priority, and keeps
  logs in RAM. Record the first/last sequence and retain raw `/dev/kmsg`
  headers as well. A 69-page display only yields host evidence for pages
  actually photographed/recorded. Add a short chronological protocol view
  plus the first assertion and nearby lines; keep the full log available.

## Why the shutdown audit came first (completed)

The local m1n1 source still has the following normal SSD-chain sequence:

1. `src/chainload.c:chainload_load()` initializes NVMe and reads stage2.
2. It calls `nvme_shutdown()` **before** `chainload_image()` prepares the
   jump. `src/main.c` calls shutdown again before vectoring; ordinarily that
   second call returns immediately because `nvme_initialized` is false.
3. Normal `src/nvme.c:nvme_shutdown()` deletes the I/O SQ/CQ, requests normal
   controller shutdown, waits for SHST DONE, disables CC.EN and waits for
   CSTS.RDY clear. Failures print a message but do not prevent handoff.
4. `rtkit_switch_power_state()` requests AP QUIESCED, waits for the recorded
   AP state, requests IOP SLEEP, and waits for the recorded IOP state. These
   waits must be audited for actual fresh ACKs, not just cached state values.
5. `rtkit_sleep()` incorrectly treats that Boolean result as a signed errno:
   `ret < 0` cannot detect false. It stops the CPU regardless of failure and
   returns false even on success. `nvme_shutdown()` ignores its return.
6. It attempts PMGR resets by names ANS and ANS2, ignores their returns, then
   frees RTKit buffers, SART mappings, ASC state, and NVMe queues.

This is a proven error-handling defect, **not a proven cause of this crash**.
If every operation succeeds, correcting the Boolean alone need not change
the hardware sequence. Also, PMGR `-1` can mean either a missing name or an
existing but disabled device; ANS/ANS2 are alternate names on some machines.
An absent alias alone is not evidence of reset failure.

The historical reboot experiment is still in `nvme_init()`'s error cleanup,
not this successful path. Do not move its restart-and-free sequence into
normal shutdown: firmware-visible memory must remain valid while the IOP
can access it.

the shared helper. Keep this corrective variant separate from SHUT-AUDIT.
