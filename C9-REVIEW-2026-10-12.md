## Restart matrix: criteria and limits

Each cell starts with a fresh LabOS/iBoot proxy session. Do not run upstream
and local tests consecutively in one firmware instance. Record full bootloader
source/binary hashes, board identity, live ADT/ANS manifest hash, loader flags,
kernel/DTB/initramfs hashes, reservations, allocation addresses, startup path,
and every phase result. A failed cell ends that firmware instance; no blind
retry. Serial timeout does not stop target-side code.

The ANS is 4Kn. Use namespace 1 and fixed, in-range LBAs such as 0, 1, 2,
128 and 4096. For every read, supply a 4096-byte aligned DRAM buffer, fill it
with a per-read sentinel, call `p.nvme_read(1, lba, buffer)`, read back 4096
bytes, and save SHA-256. LBA 1 must begin with `EFI PART`; fixed block hashes
must match within a cell. This issues controller commands, rather than
re-reading an old host buffer. No disk write/flush is needed for these cells.

The proxy interfaces already exist: `p.nvme_init()`, `p.nvme_read(...)`,
`p.nvme_shutdown()`. A second init reporting "already initialized" invalidates
the restart test. Require evidence of completed teardown and new initialization.

### Ambiguities to remove before spending a boot

- `nvme_shutdown()` returns void. Upstream and the active fork share the
  `rtkit_sleep()` Boolean defect: false/true becomes 0/1, the `<0` check
  catches neither, and the function stops the CPU and returns zero. Capture
  actual AP QUIESCED and IOP SLEEP ACKs; zero or a normal proxy return is
  not proof of successful sleep. Do not fix that bug in only one control.
- `pmgr_reset("ANS") == -1` may mean the alias does not exist. Capture
  resolved device name, active state and result separately for ANS/ANS2;
  absent alias and inactive device are different outcomes.
- Restart loops can wait indefinitely inside RTKit. Record the last phase
  and use a host deadline, then recover to a fresh session; the deadline
  is a recording bound, not target cancellation.
- Pinned upstream may need the existing CTRR reservations for a Linux
  SMP handoff. Test U's proxy restart first; distinguish untouched upstream
  from upstream plus a documented boot-only reservation patch.
- The audited stage1 has a fixed 20-second post-shutdown hold. Keep it
  matched in comparisons meant to reproduce that path, or explicitly label
  a different path. Do not silently turn C9 into a delay experiment.
- **Stock `linux.py` does not establish Linux serial logging here.** Current
  cmdline is `console=tty0`, and m1n1 tears down USB before handoff. Its
  `iface.ttymode()` is not a kernel-console transport. L/R/parity cells need
  a demonstrated reporting route that establishes the intended outcome.
  The owner subsequently authorized bounded fixed-screen camera reporting,
  validated by L0/L1. It supplies a result panel, not a raw kernel log.
  The existing camera pager remains parked. Serial m1n1 U/F/FR cells do not
  have this dependency. Do not promise a full Linux crash capture over the
  existing proxy connection without proving the transport.

## SART capture protocol

The captured live ADT identifies **SARTv3**, bus `0x285c50000`, AP
`0x485c50000`, reg[0] length `0xc000`. Refresh identity from the actual
session's ADT. Do not infer version from another board. Record reg[1]/reg[2]
addresses as metadata, but do not guess their register semantics or probe
them. ADT's `power-canary-offset=0` and `sart-power-reg-offset=0x13e8`
are metadata, not authorization to treat arbitrary offsets as readable
power-state registers.

Capture **all 16 slots**, including empty/protected ones. For slot `i`:

| Raw 32-bit register | Offset from reg[0] | Decoded value |
|---|---|---|
| CONFIG | `0x00 + 4*i` | Preserve full word; flags used by current driver are low 8 bits. Preserve upper bits separately. |
| PADDR | `0x40 + 4*i` | Physical base = `u64(raw) << 12`. |
| SIZE | `0x80 + 4*i` | Byte length = `u64(raw) << 12`; interval `[base, base+length)`. Flag bits remain opaque permissions. |

Store 48 words, phase ordinal, device prefix, timestamp, mapped base/version,
and validity status in a preallocated DRAM record. Capture CONFIG before
and after each slot's address/size reads; retain both if they differ.
Do not call an unstable table unchanged. Prefer target-side bounded reads
and defer printing until outside the transition; 48 host RPCs interposed
in a reset sequence would materially change the experiment.

Capture moments for the m1n1 U/F cells:

1. **S0:** before first NVMe init, powered/accessible baseline.
2. **S1:** after first successful init/read; annotate all RTKit buffers and
   queue regions as physical intervals and ownership/lifetime.
3. **S2:** after IO queue deletion/controller disable, before RTKit sleep.
4. **S3:** after AP QUIESCED + IOP SLEEP completion and CPU stop, before PMGR
   reset. Record actual ACK evidence separately from the broken outer result.
5. **S4:** after each resolved PMGR reset returns with reset deasserted,
   before `rtkit_free` / `sart_free` / queue frees. Record which reset occurred.
6. **S5:** after RTKit/SART release, before a second init. These removals
   are expected ownership changes; distinguish them from S3→S4 reset effects.
7. **S6:** immediately after the second `sart_init` has read hardware and
   marked protected slots, before new RTKit buffer allocation/CPU start.
8. **S7:** after second init/read or at first safe failure boundary.

For Linux L/R: capture probe baseline before/after protected-slot marking;
just before reset assert; after reset deassert and RTKit reinit, before
CPU RUN; and after buffer allocation / successful boot / safe failure.
Save `protected_entries` and `used_entries` with each snapshot. In m1n1,
capture `protected_entries`; there is no corresponding used-entry field.
Correlate slots with actual allocation addresses, not just occupied masks.

Do not read ANS CPU_CONTROL/BOOT_STATUS while reset is asserted: earlier
tests wedged there. SART capture also requires a mapped, powered, readable
block; mark unavailable phases explicitly rather than forcing a read through
reset or gated hardware. A missing snapshot is not an unchanged table.
Capture PMGR state through already identified device registers, with exact
raw words, rather than sweeping MMIO. Do not add power writes for this protocol.

**A changed table** is a per-index raw CONFIG/PADDR/SIZE difference.
Classify S1→S2→S3 (shutdown), S3→S4 (reset), S4→S5 (release), and S5→S6
(reprobe) separately. Report protected nonzero entry becoming disabled,
same occupied slot changing base/size/flags, newly enabled slots, and software
mask/hardware disagreement. An unchanged occupied mask can hide every
address/size change. Expected free/reallocation is not reset corruption.

For a shared buffer, verify its complete physical interval is covered by
an active SART interval at the relevant moment and does not overlap memory
the next stage can reclaim. Coverage is a check, not proof that all required
DMA targets are known. A stable table does not eliminate a buffer-content,
power or translation issue; a changed table does not establish causation
without the ownership/reset chronology. No SART writes or guessed repairs.

After the restart matrix, use **one grouped parity screen** if a Linux cold
test is still justified. Remove EP7 handling/start, the early controller
disable and the extra third branch together; retain the known T8132 register
support, DT/CTRR requirements, same components and reporting method. Restore

T8132 hardware support. Prove a warm control on the parity build first.

This is a screening test, not clean attribution. EP7 can affect the boot
exchange; the early `nvme_disable_ctrl()` runs **after successful RTKit boot**
and cannot directly trigger this earlier crash in the same reset attempt.
The extra third branch is not taken in the recorded ANSBR 2 runs. Those
facts make three separate cold boots poor first use of scarce boots.

If grouped parity succeeds, restore one delta at a time, beginning with
EP7, to attribute the change. If it fails identically, that configuration
did not fix the crash; it does not prove all three deltas individually
irrelevant, since masking and interactions remain possible. If the failure
moves to controller enable after RTKit succeeds, report that distinct outcome
instead of calling it the same failure. The subsequent

warm PASS, cold FAIL with branch 2, ANS crash, reset `-62` and no namespace.

## m1n1 shutdown contract and decisive comparison checklist

[T8132 support commit 53f8ee9b](https://github.com/AsahiLinux/m1n1/commit/53f8ee9b)
splits NVMMU operations onto ANS reg[3] and NVMe onto reg[9], with extra
IO queue address writes. Those changes are present locally. They establish
queue setup, not successful cold restart of this 27-family image.

Compare [pinned upstream NVMe](https://github.com/AsahiLinux/m1n1/blob/57a9339ffd1876e78297b17d34dece8cff8fa1ba/src/nvme.c),
[RTKit](https://github.com/AsahiLinux/m1n1/blob/57a9339ffd1876e78297b17d34dece8cff8fa1ba/src/rtkit.c),
[SART](https://github.com/AsahiLinux/m1n1/blob/57a9339ffd1876e78297b17d34dece8cff8fa1ba/src/sart.c)
and [PMGR](https://github.com/AsahiLinux/m1n1/blob/57a9339ffd1876e78297b17d34dece8cff8fa1ba/src/pmgr.c)
against the actual stage1 lineage:

- `nvme_init`: ADT reg[3]/reg[9] selection, die resolution, queue alignment,
  NVMMU register bases, RTKit boot, BOOT_STATUS `0x1300`, linear SQ,
  queue-size `0x1210`, admin ASQ/ACQ, IOQ addresses `0x1200`/`0x1208`.
- `nvme_exec_command`: zero TCB opcode, no data DMA flags when no PRP,
  barriers, completions and invalidation. These fixes already exist; do not
  reimplement them.
- Successful `nvme_shutdown`: delete SQ then CQ; controller normal shutdown
  and SHST DONE; clear CC.EN and RDY; AP QUIESCED then IOP SLEEP; stop CPU;
  resolved PMGR reset(s); release RTKit/SART/ASC and queue allocations;
  finally clear `nvme_initialized`. Record each result even when the caller
  ignores it. Upstream does not promise to leave an iBoot-like warm ANS.
- `rtkit_boot`: starts CPU and sends INIT unconditionally. Linux cold
  `apple_rtkit_boot()` instead waits for unsolicited boot exchange; successful
  m1n1 restart therefore does not prove identical Linux cold behavior.
  This is a comparison boundary, not justification to repeat the refuted INIT
  experiment.
- `rtkit_sleep`, `rtkit_free`, SART add/remove/free and protected masks:
  verify ACKs before memory release, surviving entries and buffer lifetimes.
- `pmgr_reset_device`: resolve the real device; capture active state, reset
  assertion/deassertion and order. Compare die and parent power state.
- `chainload_load`, `chainload_image`, `main` and kboot: identify both shutdown
  calls, which is a no-op, the audit hold, memory relocation, heap advancement
  and CTRR reservations. Match stage1/stage2 prefixes and loader flags.

## FAR lookup and optional SPTM question

The offline binary audit recursively visits 433 nodes and checks 544 scalar
register ranges, with zero decoding errors. Neither bus `0x29f008000` nor
translated AP `0x49f008000` belongs to a register range. The arm-io ranges
mapping does translate the former into the latter. This closes the requested
bus-form lookup; it does not prove FAR is a valid physical address or identify
its firmware virtual mapping. The script deliberately avoids the local
ADT helper's incomplete `walk_tree()` traversal.

On SPTM, Grok's narrower claim is supported by the primary report. The
[7.2 report's SPTM section](https://asahilinux.org/2026/08/progress-report-7-2/#they-wont-stop-thinking-different)
describes SPRR/GXF emulation that permits loading SPTM and modified XNU under
m1n1 and observing MMIO on M4+, with slower tracing. A blanket claim that
M4 SPTM makes macOS hypervisor tracing impossible is outdated. This does not
validate the installed local HV code, exact macOS build or this J604 setup;
HV tracing is not scheduled by this review.

need an O_DIRECT-capable harness, aligned buffers/offsets/lengths (at least
4096-byte alignment here), completion/error accounting and a verified Linux
reporting route. The current diagnostic init uses buffered `Pread`, so its

owner-confirmed disposable purpose; a reported 60 GB root partition is not

after a fresh boot. This review neither selects a scratch partition nor
